# FlacSplitter

Минималистичная программа для Windows 10/11 x64: разделение одного FLAC- или APE-альбома по файлу CUE с сохранением треков рядом с исходным CUE.

## MVP

- Открытие `.cue`, предварительный просмотр треков и выходных имён.
- Жирные заголовки таблицы; щелчок по существующему файлу в колонке «Выходной FLAC» открывает его проигрывателем по умолчанию в Windows. Если трек ещё не создан, приложение предложит сначала разделить альбом.
- Пользовательская маска имени файла и последняя успешно открытая папка CUE сохраняются в `config.json` рядом с EXE. Диалог открытия CUE начинается с этой папки; если папка недоступна — с домашней.
- FLAC → FLAC: FFmpeg **без перекодирования** (`-c:a copy`), с перенумерацией FLAC-фреймов и обновлением CRC.
- APE → FLAC: FFmpeg декодирует APE и кодирует каждый трек во FLAC без потери качества. Границы по `INDEX 01` задаются с точностью до PCM-сэмпла, без промежуточного файла.
- Независимо от исходного формата в таблице показываются имена будущих файлов `.flac`.
- Теги и обложка исходных FLAC/APE (при поддерживаемом формате изображения), UTF-8 и Windows-1251 в CUE.
- Без перезаписи существующих файлов.
- Портативная сборка Windows через GitHub Actions / PyInstaller, версия `0.1.<pipeline>`.

## Маска имени

По умолчанию: `%n. %a - %t`.

| Код | Значение |
| --- | --- |
| `%N` | Количество треков |
| `%n` | Номер трека (с ведущим нулём) |
| `%A` | Исполнитель альбома |
| `%a` | Исполнитель трека (или альбома) |
| `%T` | Название альбома |
| `%t` | Название трека |
| `%c` | Комментарий/описание альбома |
| `%y` | Год |
| `%g` | Жанр |
| `%%` | Символ `%` |

Недопустимые в именах файлов Windows символы (включая `?`, `:`, `/`, `\\`, `*`, `|`, `\"`, `<`, `>`) **удаляются**, а не заменяются. Например, `01. Света - Что мне делать?` становится `01. Света - Что мне делать.flac`. В FLAC-теге `TITLE` исходный знак `?` сохраняется. Корректные Unicode-символы, включая русский мягкий знак, не изменяются.

При первом запуске создаётся `config.json` возле исполняемого файла:

```json
{
  "filename_mask": "%n. %a - %t",
  "last_cue_dir": ""
}
```


Поле `last_cue_dir` заполняется автоматически абсолютным путём к папке после открытия корректного CUE — как через диалог, так и перетаскиванием файла. Если настройка отсутствует в старом `config.json`, используется домашняя папка пользователя. Изменение маски не стирает запомненный путь.

## Ограничения первой версии

CUE должен ссылаться на **один** существующий файл FLAC или APE. Если в старом CUE указано отсутствующее `.wav`, приложение ищет одноимённый `.flac` или `.ape` (при наличии обоих просит уточнить CUE). Для треков используются метки `INDEX 01`; участок до первой метки `INDEX 01` не включается в треки, промежутки перед следующими треками относятся к предыдущим. В версии MVP не поддерживаются CUE с несколькими аудиофайлами, скрытые треки как отдельные файлы, редактирование тегов и пакетная обработка. Оригиналы никогда не изменяются.

## Как работает разделение

- Для FLAC используется описанный ниже режим `copy` без потери сжатых данных.
- Для APE используется декодирование и повторное **lossless**-сжатие во FLAC: это не ухудшает звук. FFmpeg ищет позицию немного раньше трека, а фильтр `atrim` обрезает аудио строго по границам сэмплов. После обрезки `asetnsamples` собирает аудиоблоки допустимого для FLAC размера без добавления тишины и без потери сэмплов; паузы из CUE не вырезаются. Временных полных копий альбома не создаётся.

## Как работает режим copy

- FFmpeg читает таймкоды `INDEX 01` из CUE и **копирует исходные сжатые FLAC-фреймы** с опцией `-c:a copy`; декодирование и повторное сжатие аудио не выполняются.
- Используется поиск `-ss` после `-i`, чтобы соседние треки не дублировали один и тот же FLAC-фрейм.
- **Защита от щелчка на переходе:** при наличии в CUE интервала `INDEX 00` → `INDEX 01` и достаточной его длительности граница сдвигается приблизительно на два FLAC-блока назад (обычно около 0,21 секунды для 44,1 кГц). Это не даёт `-t` захватить начало следующей песни в конец предыдущего файла. Пауза не удаляется: малая её часть переходит в начало следующего FLAC. Совокупные PCM-сэмплы остаются без изменений.
- Если `INDEX 00` отсутствует или промежуток слишком короткий, граница остаётся по `INDEX 01`. Без перекодирования нельзя гарантированно убрать щелчок на произвольном ненулевом сигнале: в таких случаях требовалось бы точное редактирование PCM в области разреза.
- **Ограничение:** FFmpeg не может разрезать сжатый FLAC-фрейм пополам без перекодирования. Поэтому фактическая граница может немного отличаться от указанной в CUE. CUE задаёт целевое время разреза, а фактически берётся ближайшая подходящая граница фрейма.
- После `copy` исходная нумерация FLAC-фреймов остаётся альбомной. Программа **перенумеровывает фреймы с нуля** и пересчитывает CRC8 заголовков и CRC16 фреймов, не изменяя сжатых аудиоданных. Это необходимо для корректного воспроизведения отдельных треков многими проигрывателями. Число сэмплов в `STREAMINFO` обновляется; MD5 исходного альбома сбрасывается в ноль (разрешённое значение **«не указана»**). В `flac -t` возможно предупреждение об отсутствии MD5, но проверка аудиофреймов проходит.
- Существующие FLAC-файлы не перезаписываются; имена задаются маской и сохраняются в папку CUE.

Это выбранный компромисс ради **отсутствия повторного кодирования**, а не режим сэмпл-точного разрезания.

## Разработка

Для запуска на Windows необходим Python 3.13:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-build.txt
python main.py
python -m unittest discover -s tests -v
```

Разместите `ffmpeg.exe` рядом с `main.py` или в `PATH`. После CI сборки FFmpeg расположен рядом с EXE. Исходный код — MIT. Подробнее о сторонних лицензиях см. `THIRD_PARTY_NOTICES.md`.
